# v1.0.2 自动定位与七单样例修复

后续区域定位扩展已覆盖本文早期“粗区域不落点”的限制，当前行为以[区域定位说明](AREA_MAP_V1.0.2.md)为准。
导入日志 `7b4ce57c` 的“解析完成”快照包含 7 条原始解析订单和 7 条筛选后订单。地图上的 3 个点代表已落点数量，并非只解析出 3 条订单。

定位缺失的原因包括：一次性线上试课被当成整单的上课方式、编号标题后面的紧凑地址没有被提取，以及地理编码返回了行政区/道路/多个候选地点。

## 改动

- 保留原有七单切分，包含价格后面直接粘连下一个编号的格式。有常规地址时忽略一次性“第一节课线上试课”对常规方式的影响；明确的常规线上课程继续保留为线上。
- 识别 `编号【初中全科某区】某街道某小区3栋 初3男生` 中的具体地址。新增地址范围也用于模型请求前脱敏，原始订单不改写。现有会话首次进入结果页按新字段规则重筛一次。
- 结果页自动查询当前已应用条件下保留订单的未缓存地址，重复地址合并。只有完整地图凭据和默认城市已配置时启动；草稿改动不改变查询范围。距离大小或未知均不会排除订单，符合其他筛选条件的订单继续参与定位。
- 移除“定位筛选结果”和“开始定位”入口，每完成一个地址即刷新地图和距离。保留进度、取消、主动继续和失败后的主动重试；取消或失败后，普通刷新和再次应用条件不会自动重试。
- 新的落点完成或应用筛选改变落点范围时，地图自动调整视野展示当前订单。普通页面重绘、修改筛选草稿和仅改变排序时保留用户的平移与缩放。
- 定位请求只发送城市、地址；不会发送原始订单、报酬或模型密钥。不自动购买额度、不自动切换服务商。
- 地理编码结果过粗或不唯一时，最多补一次地标搜索。唯一候选须核对名称、城市和原文提供的区县；连锁店还须核对道路。采用 POI 时显示约略位置，不将搜索排名当作可靠性证明。仍不可靠的订单保留在列表，显示未落点原因和距离未知。
- 已成功定位的缓存和人工确认位置直接沿用。旧规则留下的未定位/多候选缓存会补查一次；新规则的最终未找到或多候选结果不会在每次重绘时重复请求。
- 页面分别显示已解析数量、当前保留数量和地图显示数量，避免把落点数量误认为解析数量。

## 验证边界

回归用例保留七条订单的编号和粘连格式，地点使用合成文本。测试涵盖模型成功和失败降级、七单导入到自动落点、旧会话字段修正、脱敏、缓存复用、过滤查询范围、取消、额度暂停、主动重试与旧缓存升级。

浏览器测试用离线 SDK 和模拟 REST 返回验证自动落点、筛选后地图/卡片联动、删除启动按钮、刷新不重复查询、手机布局等。没有用真实凭据调用高德；实际地址能否获得足够可靠的结果仍由高德返回决定。仅有道路或多个无法消歧的地点，不保证自动生成落点。
