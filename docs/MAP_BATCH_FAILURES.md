# 地图队列在 7/20 暂停的修复

2026-10-24 的导入日志包含24条解析成功的订单和多次地图更新。截图的7/20是已处理地址数，而非订单解析数；地址会去重，已有缓存及线上订单不会重新查询。原日志未保存高德响应错误码，因此无法从该日志确认当时的上游错误或准确失败地址。

已确认的代码问题：`batch_step()` 对全部 `MapAPIError` 都暂停整批任务，单个地址查询错误也会阻塞后面的地址；`locate()` 内部的POI、区域补查之间原先没有请求间隔。

## 修改后的行为

- 单地址参数错误、服务忙及其他带数字错误码的普通查询失败：保存失败原因，已处理数加一，继续下一地址。失败不会被当成“未找到”，订单仍保留。
- 额度、频率、权限错误，以及无法确认返回格式的异常、网络连接故障、本地缓存写入故障：保留整批暂停及手动恢复。
- 显示安全的接口名称和数字错误码，不展示上游原始错误、请求URL或密钥。暂停时显示当前地址；结束时显示失败数量和详情。进度和失败原因同时写入地图更新事件备注，之后导出的导入日志可据此诊断。
- 真实REST请求在本进程内至少间隔1秒，包括同一地址内的POI/区域补查。没有新增自动重试；明确的限流仍暂停。
- 点击“重试失败地址”只重查当前筛选中失败的地址，成功项沿用缓存。旧暂停任务可点击“重试未完成定位”继续。

错误码类别参考[高德官方错误码说明](https://lbs.amap.com/api/webservice/guide/tools/info/)，例如10016表示服务繁忙，10021表示接口QPS超限。
