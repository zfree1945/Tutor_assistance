# v1.0.2 区域约略定位

订单地点只有道路、街道或片区时，地图现在显示区域参考标记，并保留“具体上课地点待确认”。定位结果继续区分原始候选与展示参考点，不把区域中心当成已确认的上课地址。

## 覆盖情况

| 原文或返回情况 | 地图行为 |
| --- | --- |
| 唯一门牌、小区、学校、建筑 | 保留原有精确／地标约略定位 |
| 道路、大道、路口 | 使用可核对的道路参考位置 |
| 街道、乡镇 | 显示街道或乡镇参考位置 |
| 村庄、社区 | 显示村庄或社区参考位置 |
| 园区、商圈、开发区、校区 | 使用匹配地标或区域参考位置 |
| 学校、医院、商场、超市、体育馆、地铁／公交站附近或对面 | 显示已核对的地标参考点，保留实际地点待确认 |
| 一个地标的多个出入口、相近同名候选 | 城市、原文区县与名称一致，候选两两不超过1.5公里时，显示候选范围的代表点，保留原始候选 |
| 建筑无法定位，但原文包含道路、街道、区县 | 从具体到宽泛最多补查3个原文区域 |
| 多个候选相距较远 | 不取第一项或计算跨区域中心；可尝试退到原文明确的共同道路、行政区 |
| 原文只明确到城市 | 可显示有依据的城市参考点；不单凭默认城市给未知地址落点 |
| 仅线上、缺少地址、省／国家级结果、未知精度或异地冲突 | 保留待确认，不构造订单位置 |

原地址地理编码和必要的一次POI搜索之外，区域回退最多增加3次地理编码；每个地址最多5次请求，成功取得参考区域后立即停止。只向高德传送清洗后的城市、地址及其原文地名，不传送订单原文、报酬、联系方式。额度不足、权限或连接错误仍立即中断，不在区域回退中自动重试。

## 展示和筛选

- 出发点与图例共用房屋图标。明确匹配使用绿色实线边框，可能匹配使用橙色虚线边框；边框样式与定位精度独立。
- 区域参考位置和地标约略位置均在订单编号前显示“约”，表示大致定位。聚合标记含大致定位时也显示“约”，含可能匹配订单时使用虚线边框。
- 点击区域标记可查看地名、实际地点待确认说明、订单信息和参考距离，并联动对应订单卡片。
- 不绘制没有真实边界依据的圆或多边形。聚集候选的代表点只用于展示，不表示实际授课点或保证范围。
- 区域点显示整数公里的参考距离，实际距离保持未知；距离排序按未知项处理。已取消按距离过滤，区域点订单和其他距离未知的订单始终保留。
- 明确地点／小区约略位置继续显示距离并参与排序，用户保存的位置优先。
- `GeoResult.area_point` 可独立于原始 `candidates` 保存；旧缓存缺少该字段仍能读取。定位规则版本升级为3，旧版未定位／多候选缓存补查一次，成功位置与用户确认位置复用。

## 区域参考点的不确定性分档

`precision="area"` 的参考点通过可选字段 `area_scale` 表示范围大小，不代表测量误差或真实边界。

| 档位 | 来源 | 展示说明 |
| --- | --- | --- |
| small | 已核对的唯一附近地标、相近地标候选的代表点 | 附近地标参考，范围较小；保持正常明度 |
| medium | 道路、社区、村庄、商圈 | 道路或社区参考位置；标记略淡 |
| large | 街道、乡镇、区县、市、开发区，或逐级回退至街道及以上 | 范围较大，仅供参考所在片区；标记最淡 |

所有区域标记保留编号前的“约”，混合聚合标记采用其中范围最大的档位。旧缓存缺少 `area_scale` 时正常读取，按 medium 渲染。此次保持 `LOCATION_REVISION=3`，不迁移、清空或失效现有缓存，也不触发全量补查。分档只改变标记与原有弹窗说明，不绘制圆或多边形，不改变距离计算与排序。

## 验证边界

测试覆盖模拟高德响应、城市与区县冲突、分散候选、逐级回退、请求上限、额度中断、持久缓存、旧批次升级、距离排序及桌面／手机标记弹窗。浏览器使用离线SDK，不代表真实高德底图或每条实际订单地址已经现场验证。

接口字段依据：[高德地理编码文档](https://lbs.amap.com/api/webservice/guide/api/georegeo)、[高德POI搜索文档](https://lbs.amap.com/api/webservice/guide/api-advanced/search)。
